## What is Sail

Sail is an ISA specification language for defining processor instruction-set semantics. The compiler is implemented in OCaml and takes `.sail` source files as input, producing outputs including C emulators, theorem-prover definitions (Coq, Isabelle, HOL4), Lean 4, SystemVerilog, and SMT formulas.

## Build and Install

```bash
dune build --release   # build the sail binary
dune install           # install
make clean             # clean
```

Dependencies: `opam`, `z3`, `libgmp-dev`. Install deps with `opam install . --deps-only`.

## Formatting

OCaml formatting is enforced by CI. Format with:
```bash
dune fmt
```
Config is in `.ocamlformat` (profile: default, version: 0.27.0, margin: 120).

## Running Tests

Use `SAIL=\`pwd\`/sail` to run tests — `sail` is a script in the repo root that invokes the dev build with plugins loaded and `SAIL_DIR` set automatically:

```bash
# Core tests (no external tool deps: lexing, typechecking, OCaml, float, pattern completeness)
SAIL=`pwd`/sail test/run_core_tests.sh

# All tests (requires z3, cvc4, etc.)
SAIL=`pwd`/sail test/run_tests.sh

# Individual test suites (all in test/suites/)
SAIL=`pwd`/sail test/suites/typecheck.py
SAIL=`pwd`/sail test/suites/exec.py

# Run a single named test
SAIL=`pwd`/sail test/suites/typecheck.py --test <testname>

# Update expected output for a test
SAIL=`pwd`/sail test/suites/typecheck.py --update-expected
```

The Makefile shortcuts use the same `sail` script:
```bash
make core-tests   # equivalent to SAIL=`pwd`/sail test/run_core_tests.sh
make test         # all tests
make exec-tests   # exec backend tests only
```

## Architecture

### Source Layout

- `src/bin/` — Main entry point (`sail.ml`), CLI options (`sail_options.ml`), REPL
- `src/lib/` — Core compiler library (`libsail`), used by all backends
- `src/sail_c_backend/` — C code generation
- `src/sail_lean_backend/` — Lean 4 output
- `src/sail_coq_backend/` — Coq output
- `src/sail_lem_backend/` — Lem output
- `src/sail_ocaml_backend/` — OCaml output
- `src/sail_sv_backend/` — SystemVerilog output
- `src/sail_smt_backend/` — SMT/property checking
- `src/sail_doc_backend/` — Documentation (LaTeX/AsciiDoc)
- `language/` — `jib.ott` grammar for the Jib IR
- `test/` — Test suites, one subdirectory per backend/feature

### Compilation Pipeline

1. **Parse** — `.sail` files → parse AST (`src/lib/parse_ast.ml`, generated by ott)
2. **Initial check** (`src/lib/initial_check.ml`) — Desugars parse AST to main AST; handles `$include`, `$ifdef`, etc.
3. **Type check** (`src/lib/type_check.ml`) — Bidirectional type checker; uses Z3 (via `constraint.ml`) for numeric/bitvector constraints; produces a fully-annotated typed AST
4. **De-scatter** (`src/lib/scattered.ml`) — Merges scattered function/union clauses into single definitions
5. **Rewrites** (`src/lib/rewrites.ml`) — Target-specific AST-to-AST rewriting passes (monomorphisation, specialisation, etc.)
6. **Backend** — Each backend is registered as a "target" (see `src/lib/target.ml`) and receives the rewritten AST

The frontend entry point that orchestrates steps 1–4 is `src/lib/frontend.ml`.

### AST Conventions

- The main Sail AST is in `src/lib/ast.ml`, which re-exports `src/lib/extraction/Ast.ml` — code extracted from the Rocq (Coq) definitions in `src/lib/rocq/theories/`. Do not edit the extraction directory by hand; regenerate with `make extraction`.
- Every AST node uses an `_aux` wrapper carrying a location annotation: `E_aux of exp_aux * annot`
- `annot = l * 'a` where `l` is always a location; single variable `l` always means location in the source
- Type variables are called "kids" (they have kinds: `Int`, `Bool`, `Type`)
- Utilities: `ast_util.ml` (constructors like `mk_exp`, sets/maps of identifiers), `ast_compare.ml`
- The parse AST (`parse_ast.ml`) is separate and contains extra syntactic sugar not in the main AST

### Jib Intermediate Representation

The C and SMT backends lower Sail through a custom IR called Jib (files in `src/lib/` with `jib_` prefix, plus `src/lib/anf.ml`):

1. Sail → A-normal form (`anf.ml`)
2. ANF → Jib (`jib_compile.ml`) — simpler types (`ctyp`), no polymorphism; SMT uses SMT to fit arbitrary-precision types into fixed-width machine types
3. Jib → SSA (`jib_ssa.ml`) — used by the SMT backend to generate SMTLIB
4. Jib optimisation (`jib_optimize.ml`)

### Target/Plugin System

Backends register using `Target.register` in `src/lib/target.ml`. Each target specifies:
- A name and CLI flag (e.g., `-c`, `-lean`, `-coq`)
- A list of rewrite passes to apply before the backend runs
- An action function receiving the typed, rewritten AST

The `opt_` prefix convention is used throughout for mutable global option variables (set at startup, then immutable).

### Test Infrastructure

Test suite scripts live in `test/suites/` (e.g. `typecheck.py`, `exec.py`, `lean.py`) and use the shared `test/sailtest.py` helper. Test data remains in the per-backend directories (e.g. `test/typecheck/`, `test/exec/`). Tests fork processes and compare output against `.expect` files. The `--update-expected` flag regenerates expected output and `--test <name>` runs a single test.
